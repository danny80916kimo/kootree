# 完整參考版後台整合

介面參考：https://kootree-hanitu.nelsliu9121.workers.dev/dashboard/

`dashboard_supabase.py`（本機工作區為 `app.py`）沿用完整參考版的版面與互動：

- 插畫頁首、篩選側欄、八個 KPI，待確認通報及高風險 KPI 可連至案件資料中心。
- 五種地圖圖層、完整逐棵點位（移動後依視窗範圍載入）、淡色底圖、下方圖例。
- 樹木／官方移除移植公開說明雙分頁，主題搜尋、原文閱讀、CSV、目的地連線。
- 全年養護觀察卡片，當月 KPI 與勾選月份篩選仍採 Supabase 有來源的規則。
- 六張圖：樹種圓環、12 區數量、確認狀態堆疊通報圖、通報率點圖、路段巡檢氣泡圖、待確認通報天數。
- 樹種／行政區／通報類型／路段圖表支援點選鑽取及再次點選還原；樹種圖例亦可篩選。
- 案件與養護資料中心：待確認通報、高風險樹木、養護工單、歷史趨勢、逐樹履歷及目前分頁 CSV。

## 資料不應複製參考站的示範數字

樹籍、通報、風險及月份來源仍是 Supabase。參考站以程式生成的班組、巡檢日、派工與結案日期不會自動移植。多筆通報關聯同一樹仍按通報件數計算；已確認不等於已結案。樹高及胸徑保留來源值，不猜測單位；調查日期缺漏不以建檔日期代替。

官方公開說明表 `dashboard_official_cases` 由 `supabase/seed_dashboard_official_cases.sql` 匯入。此資料與參考站相同，共 76 則公開說明、66 則可定位、20 筆目的地描述；不是逐株移除／移植執行清冊。腳本可重複執行，以相同 ID 更新，不刪除樹籍或市民通報。

養護工單由 `dashboard_work_orders` 讀取，欄位契約在 `supabase/dashboard_work_orders_schema.sql`。此腳本僅建置資料表，不生成虛構工單。`is_simulated` 明確隔離展示資料；工單狀態與通報確認狀態獨立。未建立或無讀取權限時顯示資料來源缺漏，不把缺漏當成零件已處理。

歷史趨勢採已有的通報日期；沒有結案日期時不產生結案曲線。官方與工單資料啟動後快取，資料更新後重新啟動後台。
